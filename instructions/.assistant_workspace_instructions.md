# Workspace data engineering rules
- All development and staging tables belong in `<domain>_dev` schemas. Never modify production tables directly from ad hoc notebooks.
- Every production table and column must have a clear Unity Catalog comment before sign-off.
- Use Unity Catalog metric views and Genie Ontology Pages for company KPIs (MRR, churn, active customers) instead of re-deriving formulas in SQL queries.

# Safety guardrails
- Ask for confirmation before running `DROP`, `TRUNCATE`, `OVERWRITE`, or `GRANT` statements.
- Never hardcode credentials, tokens, or personal access keys in notebooks, queries, or comments.
- Prefer Delta Lake and Unity Catalog three-level namespaces (`catalog.schema.table`) in all examples.
